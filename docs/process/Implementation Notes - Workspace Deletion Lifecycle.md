# Workspace Deletion Lifecycle

Workspace deletion is an admin-only Workspace Settings action. The client calls the ServiceNow runtime workspace-delete route and does not replay the command automatically.

The server resolves the workspace by sys_id or slug, rechecks workspace-admin capability, resolves the owned cleanup IDs, and asks the global workspace-membership bridge to validate the generated admin/editor groups through a non-destructive `validate_workspace_group_deletion` member-mutation command. If any preflight step fails, deletion stops before workspace-owned data is mutated and the workspace remains active. The global bridge only validates or deletes group pairs that still belong to the workspace and whose names match the generated Docsera workspace group patterns.

After preflight succeeds, the scoped service commits the deletion by marking the workspace inactive while preserving cleanup references needed by the in-flight operation. From that point forward, failures are treated as committed-but-incomplete cleanup: the workspace remains inactive and unavailable, and the client must leave the workspace instead of reporting that nothing was deleted. Cleanup then follows the real ownership graph: generated groups; edit locks by page; workspace/media/icon attachments; member mutation commands; mutation claims; change entries and removal batches by change set; removal members by removal batch; page snapshots by snapshot set; and direct workspace-owned edit leases, icon assets, snapshot sets, change sets, and pages through fields that exist on those tables. The service verifies the generated groups, attachments, edit state, icon assets, pages, change sets, snapshot sets, and workflow children are gone before it finalizes the inactive tombstone. The finalized tombstone preserves the slug while clearing group pointers, change-set pointers, and uploaded-icon references so old workspace URLs do not silently bind to a future workspace.

On success, the client closes workspace overlays, clears the stored workspace edit lease for the deleted workspace, removes the deleted slug from recent-workspace state, refreshes launcher data, and routes to the workspace launcher. On pre-commit failure, Workspace Settings remains recoverable and displays the returned error. On committed cleanup failure, the route marks the failure as `deletionCommitted`, the client removes the inactive workspace from local navigation state, clears workspace context, refreshes launcher data, and routes to the workspace launcher.
