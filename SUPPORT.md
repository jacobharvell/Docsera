# Support

Docsera's public support workflow is intentionally lightweight.

## Installation help

For installation help, first follow the [Docsera 0.1.0 package instructions](releases/0.1.0/README.md), including the stated artifact order and checksum verification. If the issue remains, open a public GitHub issue with the ServiceNow release/version, the artifact name, the installation step that failed, and non-sensitive error details.

## Defects

Use the [bug report template](.github/ISSUE_TEMPLATE/bug_report.md) for reproducible problems in supported Docsera behavior. Include steps, expected and actual behavior, and safe environment details. Do not include credentials, tokens, private instance URLs, personal data, or security-sensitive reproduction details.

## Feature requests

Use the [feature request template](.github/ISSUE_TEMPLATE/feature_request.md) for focused product or developer-workflow proposals. Explain the problem and the expected outcome; avoid treating a feature request as a commitment or roadmap promise.

## Private security disclosures

Do not use public issues for vulnerabilities. Follow [SECURITY.md](SECURITY.md). The repository owner must enable GitHub private vulnerability reporting before public launch; once enabled, submit security reports through the repository Security tab.
